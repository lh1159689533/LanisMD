# 画板插件（Board Block）技术方案

> 版本：v1.0
> 日期：2026-07-02
> 状态：待评审
> 基础库：[Plait](https://github.com/worktile/plait)（`@plait/*`，MIT）
> 参考范式：`src/editor/plugins/mermaid-block/`（复杂图形节点样板）

***

## 一、需求概述

在 LanisMD 的 Milkdown 编辑器中新增「画板」自定义节点，提供类似语雀画板 / 飞书画板的能力：思维导图、流程图、自由画板三合一，SVG 矢量渲染，节点内可编辑富文本。画板作为文档中的一个独立块级节点存在，随 `.md` 文件持久化。

### 1.1 关键决策

| 决策项           | 结论                                                                          | 备注                     |
| ------------- | --------------------------------------------------------------------------- | ---------------------- |
| 图形引擎          | Plait（`@plait/core` + `@plait/mind` + `@plait/draw` + `@plait/react-board`） | 见第二节选型                 |
| 节点形态          | 独立 atom block 节点 `board_block`（**不**劫持 code\_block）                         | 与 mermaid 分流方案不同，见 2.3 |
| Markdown 序列化  | ` ```plait ` 代码围栏内联 JSON（MVP），后续可演进为外部附件                                    | 见第四节                   |
| 数据编码          | JSON → 压缩（`pako` deflate）→ base64，减少 diff 噪音                                | 见 4.2                  |
| React 挂载      | NodeView 内 `createRoot` 挂载 `<PlaitBoard>`，`destroy` 时 `unmount`             | 见 6.2                  |
| 文本层           | Plait 内部用 Slate（与主编辑器 ProseMirror **并存**）                                   | 最大风险点，见 7.1            |
| 视口策略          | 文档内固定高度（默认 420px，可拖拽）+ 全屏编辑覆盖层                                              | 见 7.3                  |
| Slash Command | `/board`，显示名"画板"；子项 `/mindmap`、`/flowchart` 可选                              | 见第八节                   |
| 事件隔离          | 编辑态严格吞掉键盘/输入法事件，DOM 变更全忽略                                                   | 核心，见第五节                |
| 导出            | PNG / SVG（复用 Plait 内置导出能力）                                                  | —                      |

### 1.2 注意项

1. Plait 数据含手绘贴图（base64 图片）时，内联 JSON 会急剧膨胀，此类场景需提前切换到外部附件方案（4.3）。
2. 应用内将同时存在两套富文本框架（ProseMirror + Slate），需评估包体积增量（Plait + Slate 约数百 KB），并做懒加载。
3. 画板有独立 undo 栈，与 ProseMirror `history` 需按焦点隔离（编辑态 Ctrl+Z 走 Plait）。
4. 中文输入法（IME）在 Slate 与 ProseMirror 边界最易出问题，须作为第一个 spike 验证点。
5. 多个画板同时挂载会有性能压力，预览态仅渲染静态 SVG 快照，进视口再挂载完整 Plait。

## 二、技术选型

### 2.1 为什么是 Plait

Plait 与语雀画板技术路线高度重合（SVG 矢量 + 数据驱动 + 插件架构，灵感源自 Slate），且：

* **UI 框架无关 + 官方 React 适配**（`@plait/react-board`），契合本项目 React 18 技术栈。

* **MIT License**，商用无授权顾虑（优于 tldraw）。

* 思维导图 / 流程图 / 自由画板一站式（`@plait/mind`、`@plait/draw`），自带自动布局与连线路由。

* 有开源参考产品 **Drawnix**（基于 Plait React 版），可直接借鉴集成代码。

### 2.2 依赖清单

```jsonc
// package.json 新增（版本以安装时最新稳定版为准）
{
  "@plait/core": "^0.x",
  "@plait/common": "^0.x",
  "@plait/mind": "^0.x",       // 思维导图
  "@plait/draw": "^0.x",       // 流程图 / 几何图形 / 连线
  "@plait/react-board": "^0.x",// React 宿主
  "@plait/react-text": "^0.x", // 文本层（Slate 适配）
  "slate": "^0.x",
  "slate-react": "^0.x",
  "pako": "^2.x"               // 数据压缩（可选）
}
```

> 安装用 `pnpm add`，禁止 npm/yarn。

### 2.3 节点形态：为什么不复用 code\_block 分流

mermaid-block 采用「拦截 `language="mermaid"` 的 code\_block + `$view` 分流」，因为 mermaid 的数据**本身就是用户手写的文本代码**，天然适合 code\_block（`contentDOM` 可编辑文本）。

Plait 画板不同：其数据是一坨**不该被用户手改的 JSON**。因此画板更适合做**独立 atom 节点**——ProseMirror 完全不介入其内部，节点只有 `attrs`（存数据），没有可编辑的 `contentDOM` 文本。

| 维度         | code\_block 分流（mermaid 式） | 独立 atom 节点（本方案）              |
| ---------- | ------------------------- | ---------------------------- |
| 数据可见性      | 用户能看到/编辑原始文本              | JSON 隐藏，仅图形可见                |
| remark 序列化 | 复用 code\_block 现成逻辑       | 需自定义（参考 toc/math/file-block） |
| 事件隔离       | 编辑态需放行文本编辑事件              | 编辑态全吞（更彻底、更简单）               |
| 契合度        | 低（JSON 不该当文本编辑）           | 高                            |

**结论**：采用独立 atom 节点。MVP 阶段若想极限省事，可退回 code\_block 分流方案（见第十节降级），但不推荐。

## 四、数据存储方案（Markdown 序列化）

### 4.1 存储形态（MVP：代码围栏内联）

画板数据以专用语言标签的代码围栏落盘，与 mermaid 同构，单文件自包含：

````markdown
```plait
eyJ2IjoxLCJjaGlsZHJlbiI6W3sidHlwZSI6Im1pbmQiLC4uLn1dfQ==
```
````

* 围栏 `info string` 固定为 `plait`。

* 围栏正文为**编码后的字符串**（见 4.2），非人类可读，避免大段 JSON 污染文档。

### 4.2 数据编码（codec.ts）

```
encode(elements: PlaitElement[]): string
    json      = JSON.stringify({ v: SCHEMA_VERSION, children: elements, viewport })
    deflated  = pako.deflate(json)            // 压缩，可选
    return base64(deflated)

decode(text: string): { version, elements, viewport }
    try:
        deflated = base64Decode(text)
        json     = pako.inflate(deflated, { to: 'string' })
        return JSON.parse(json)
    catch:                                    // 兼容未压缩的历史数据
        return JSON.parse(base64DecodeSafe(text) ?? text)
```

> 说明：压缩为可选优化项。MVP 可先存纯 base64(JSON) 甚至明文 JSON 跑通，确认无误后再加 `pako`。解码要对旧格式向后兼容。

### 4.3 演进：外部附件方案（后期）

当画板含手绘贴图 / 数据量大时，改为外部 `.plait` 文件 + md 引用：

```markdown
![board](./assets/board-20260702-xxx.plait)
```

需配套管理附件生命周期（创建 / 移动 / 删除 / 导出打包），可复用 `file-block` 已有的附件目录机制。本期**不实现**，仅预留 `version` 字段供未来迁移判别。

## 五、Schema 定义

`board_block` 为块级 atom 节点，无可编辑内容（`atom: true`），并 `isolating` 防止选区进入内部。

```typescript
// schema.ts —— 参考 toc-block / math-block 的 $nodeSchema 写法
import { $nodeSchema } from '@milkdown/kit/utils';

export const boardBlockSchema = $nodeSchema('board_block', () => ({
  group: 'block',
  atom: true,          // 无内部可编辑内容，ProseMirror 视为整体
  isolating: true,     // 选区/删除不穿透到内部
  selectable: true,
  draggable: true,
  attrs: {
    data: { default: '' },       // 编码后的画板数据（4.2）
    version: { default: 1 },     // schema 版本，供迁移
    height: { default: 420 },    // 文档内视口高度（px，可拖拽调整）
  },
  parseDOM: [
    {
      tag: 'div[data-type="board-block"]',
      getAttrs: (dom) => ({
        data: (dom as HTMLElement).getAttribute('data-board') || '',
        version: Number((dom as HTMLElement).getAttribute('data-version')) || 1,
        height: Number((dom as HTMLElement).getAttribute('data-height')) || 420,
      }),
    },
  ],
  toDOM: (node) => [
    'div',
    {
      'data-type': 'board-block',
      'data-board': node.attrs.data,
      'data-version': String(node.attrs.version),
      'data-height': String(node.attrs.height),
    },
  ],
  // Markdown 解析/序列化（remark 侧对接，见第六节）
  parseMarkdown: {
    match: (node) => node.type === 'code' && node.lang === 'plait',
    runner: (state, node, type) => {
      state.addNode(type, { data: (node.value as string) ?? '', version: 1 });
    },
  },
  toMarkdown: {
    match: (node) => node.type.name === 'board_block',
    runner: (state, node) => {
      state.addNode('code', undefined, node.attrs.data, { lang: 'plait' });
    },
  },
}));
```

> `parseMarkdown.match` 命中 `lang === 'plait'` 的代码节点，将其转成 `board_block`；`toMarkdown` 反向写回 ` ```plait ` 围栏。这样无需额外 remark AST 插件即可完成互转（Milkdown 的 `$nodeSchema` 内置 parse/toMarkdown runner）。

## 六、Remark 序列化

### 6.1 是否需要独立 remark 插件

由于第五节的 `parseMarkdown` / `toMarkdown` 已挂在 schema 上，且 `plait` 语言的围栏本就会被 commonmark 解析成 `code` 节点，**通常无需**再写独立 remark AST 插件。

仅当出现下列情况才需要补 `remark.ts`：

* 需要在解析前对 `plait` 围栏做预处理（如迁移旧版本数据）。

* 需要阻止 code-block 组件把 `plait` 当普通代码块渲染（注册顺序上让 `board_block` 的 `$view` 覆盖，见 7.4）。

### 6.2 序列化流程伪码

```
// 读取（md -> 节点）
parse(markdown):
    mdast = remark.parse(markdown)
    for node in mdast where node.type == 'code' && node.lang == 'plait':
        board_block.attrs.data = node.value        // 编码字符串原样存入 attrs
    // NodeView 挂载时再 decode(data) -> Plait elements

// 写回（节点 -> md）
serialize(doc):
    for node in doc where node.type == 'board_block':
        emit fenced code block, lang = 'plait', value = node.attrs.data
```

数据的 `encode`/`decode` 只在 **NodeView 边界**发生（挂载时 decode，onChange 时 encode 回写 attrs），remark 层始终把 `attrs.data` 当作不透明字符串搬运，职责清晰。

## 七、NodeView 与三大难题

NodeView 结构复刻 `mermaid-block/node-view.ts`，差异在于「渲染核换成挂载 React 子树」，且事件隔离更严格。

### 7.0 NodeView 骨架

```typescript
export class BoardNodeView implements NodeView {
  dom: HTMLElement;                 // atom 节点无 contentDOM
  private root: Root | null = null; // React 根
  private state: 'preview' | 'editing' = 'preview';
  private switchingState = false;

  constructor(node, view, getPos, autoEdit) {
    this.dom = div('.lanismd-board-block.is-preview', { 'data-type': 'board-block' });
    this.dom.style.height = `${node.attrs.height}px`;
    this.mountToolbar();     // 复用 mermaid 工具栏范式
    // 预览态：仅渲染静态 SVG 快照（懒挂载，进视口/进编辑再挂 React）
    this.renderSnapshot();
    if (autoEdit) requestAnimationFrame(() => this.enterEdit());
  }

  private enterEdit() {
    this.switchingState = true;
    this.state = 'editing';
    // 懒挂载 React + Plait
    this.root ??= createRoot(this.mountEl);
    this.root.render(
      <BoardReact
        initial={decode(this.node.attrs.data)}
        onChange={debounce(this.writeBack, 500)}
      />
    );
    requestAnimationFrame(() => { this.switchingState = false; });
  }

  private writeBack = (elements) => {
    const pos = this.getPos(); if (pos === undefined) return;
    const data = encode(elements);
    const tr = this.view.state.tr.setNodeMarkup(pos, undefined, {
      ...this.node.attrs, data,
    });
    this.view.dispatch(tr);   // 数据回写 attrs -> 触发 markdown 更新
  };

  destroy() { this.root?.unmount(); this.root = null; /* 清理监听 */ }
}
```

### 7.1 难题一：Slate ↔ ProseMirror 焦点/键盘内战 ★最关键

画板内部（Plait 文本）用 Slate。一旦光标进入画板，所有键盘、IME、选区事件都**不能**让 ProseMirror 插手，否则方向键、回车、中文输入法会两边打架。

**对策（在 mermaid** **`stopEvent`** **基础上加严）：**

* 节点设为 `atom + isolating + selectable`，ProseMirror 把它当不可分割整体，selection 不进入内部。

* `stopEvent` 在**编辑态一律** **`return true`**（比 mermaid「放行文本编辑」更彻底，因为内部由 Slate 全权接管）：

```typescript
stopEvent(event: Event): boolean {
  if (this.toolbar.contains(event.target)) return true; // 工具栏自管
  if (this.switchingState) return true;                 // 切换保护期全拦
  if (this.state === 'editing') return true;            // 编辑态全部交给 Plait/Slate
  if (event.type === 'mousedown') return true;          // 预览态拦鼠标，防选中穿透
  return false;
}
```

### 7.2 难题二：React 子树挂载 / 卸载

* 构造函数**不立即**挂载（预览态只显示 SVG 快照），进入编辑或进入视口时才 `createRoot(...).render(...)`。

* `destroy()` 里**必须** `root.unmount()`，否则切文档 / 删节点会内存泄漏。

* 数据回写：Plait `onChange` → 防抖 500ms → `setNodeMarkup` 更新 `attrs.data`（参照 mermaid `cancelEdit` 里的 `setNodeMarkup` / `replaceWith` 写法）。

* `ignoreMutation` **全部返回** **`true`**（atom 节点没有 contentDOM，Plait 自管全部 DOM，ProseMirror 绝不能去 diff/重建）：

```typescript
ignoreMutation(record: ViewMutationRecord): boolean {
  if (record.type === 'selection') return false;
  return true;   // 其余一律忽略，交给 Plait 自己管理内部 DOM
}
```

### 7.3 难题三：无限画布 vs 文档流高度

* 文档内给**固定高度视口**（默认 420px，底部拖拽手柄可调，写入 `attrs.height`），内部画布仍无限。

* 提供**全屏 / 弹层编辑模式**：点工具栏放大按钮 → 打开覆盖层沉浸编辑 → 关闭时写回数据。这是语雀/飞书通用做法，也顺带缓解 7.1 的事件冲突（全屏时 ProseMirror 完全在背景）。

### 7.4 注册与 undo 隔离

* `board_block` 的 `$view` 需在 `codeBlockComponent` 之后注册（若采用围栏方案，确保 `plait` 不被 code-block 组件抢渲染）。

* undo：编辑态 Ctrl+Z 由 `stopEvent` 吞掉 → 走 Plait 自身 undo 栈；退出编辑后交回 ProseMirror `history`。

## 十、风险评估与降级

| 维度     | 评估                                                                            |
| ------ | ----------------------------------------------------------------------------- |
| 可行性    | 高。mermaid-block 已趟平「复杂图形节点」80%，Plait 官方支持 React。                              |
| 工作量    | 中偏上。骨架 2-3 天；Slate/PM 事件隔离与 IME 调试是大头，估 1-2 周到可用。                             |
| 最大风险   | Slate ↔ ProseMirror 焦点 / 中文输入法冲突。**必须先 spike 验证**。                            |
| 次要风险   | 包体积（Plait+Slate 数百 KB）；大画板 JSON 内联的性能与 diff 噪音。                               |
| 降级方案 A | 若 React/Slate 内联事件冲突难解：退回「预览快照 + 全屏独立编辑器」，绕开内联事件共存。                           |
| 降级方案 B | 若独立 atom 节点 remark 对接不顺：退回 code\_block 分流（mermaid 式，lang=plait），牺牲数据隐藏性换实现速度。 |

## 十一、结论

* 技术上完全可行，Plait 是当前最贴合语雀画板路线、且 License 友好的开源选择。

* 本项目 `mermaid-block` 已提供成熟的「复杂图形节点」范式，集成主要工作量是「换渲染核为 Plait React」+「处理 React/Slate 挂载与事件隔离」。
